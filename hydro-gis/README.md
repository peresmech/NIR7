# HydroGIS

Локальное приложение для просмотра и администрирования гидрологических данных
гидроузлов и гидропостов. Интерфейс работает только на локальном адресе
`127.0.0.1`, база данных хранится в папке `data/hydro.db`.

## Возможности

- карта OpenStreetMap с точками объектов;
- просмотр расхода воды и уровней в верхнем/нижнем бьефе;
- графики за произвольный временной диапазон;
- режим гостя без возможности изменения данных;
- режим администратора и импорт CSV-файлов;
- журнал импорта;
- локальная SQLite-база и защитный секретный ключ приложения;
- собственное клиентское окно Qt, без запуска отдельной вкладки браузера;
- правое меню с миниатюрами графиков и просмотром поверх карты;
- выбор периода дат календарём или ползунком;
- выбор объекта кликом по маркеру карты;
- группировка объектов по области или региону;
- расчёт статистики и межгодовых показателей;
- сравнение нескольких станций;
- экспорт наблюдений в CSV и графиков в PNG;
- отметки качества, журнал действий и создание резервных копий;
- метаданные единиц, источника данных, ИСТОК и ТП;
- отдельная папка `resources` для исходной базы, справочника объектов и
  справочника объектов.

## Быстрый запуск из исходников

### Windows

1. На компьютере сборки установите Python 3.11+ и подключитесь к Интернету.
2. Один раз запустите `start_windows.bat`. Он установит зависимости, соберёт
   приложение и запустит его; это единственный этап, которому нужны Python и сеть.
3. Дальше запускайте `dist\HydroGIS\HydroGIS.exe` напрямую.
4. Для переноса скопируйте **всю** папку `dist\HydroGIS`, а не только EXE.

В готовой папке находятся EXE и Qt/Python-компоненты. На другом компьютере не
нужны Python, установка библиотек или Интернет. Сборку создавайте для Windows
той же разрядности/архитектуры. Qt WebEngine делает папку сборки большой.
GitHub хранит исходный код и сценарий сборки, а не готовый EXE.

### Linux

```bash
cd hydro-gis
chmod +x start_linux.sh
./start_linux.sh
```

При первом запуске приложение создаст локальную копию базы из
`resources/hydro.db`. Данные и резервные копии хранятся в `data/`.

## Карта и автономная работа

Карта показывает только подложку OpenStreetMap и точки объектов. Тайлы OSM
загружаются из Интернета по мере просмотра карты, поэтому подложка требует
подключения к сети. Приложение не скачивает тайлы заранее: политика стандартного
сервера OSM запрещает массовую загрузку и offline-режим
([Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)).
Без сети база, точки и аналитика доступны, но сама OSM-подложка не отображается.

Leaflet, веб-шаблоны и Python-библиотеки включаются в переносимую сборку.

## Данные и доступ

- гостевой вход выполняется по кнопке «Войти гостем»;
- учётная запись администратора: `admin` / `admin`.

Сразу после первого запуска смените пароль администратора в разделе
«Администрирование» на странице смены пароля.

Не открывайте порт приложения в интернет и не публикуйте папку `data/`.
Для резервного копирования копируйте локально `data/hydro.db`.
Файлы PNG и CSV сохраняются через диалог выбора пути (по умолчанию —
`data/exports`); после сохранения приложение показывает полный путь.

## Формат данных и импорт

Проверены все 61 CSV в корневой папке `data/`. В них три набора заголовков:

```text
Dates,Discharge,Forecast_Discharge
Dates,Absolute_Levels,Forecast_Absolute_Levels,Forecast_Levels,Relative_Levels
Dates,Absolute_Levels,Forecast_Levels,Relative_Levels
```

Файлы имеют UTF-8 с BOM, разделитель — запятая, даты — `день-месяц-год`.
Импорт также читает UTF-8 без BOM и Windows-1251. `Discharge` распознаётся как
расход; `Absolute_Levels` и `Relative_Levels` сохраняются отдельными
показателями; колонки `Forecast_*` сохраняются как прогнозные ряды, отдельно от
наблюдений. Пустые и некорректные ячейки пропускаются. В заголовках CSV единицы
не указаны, поэтому приложение использует единицы из справочника параметров:
расход — м³/с, абсолютный уровень — м, относительный уровень — см. Последняя
единица принята по формату и масштабу представленных данных; её следует
подтвердить по исходной документации.

Файлы из `data/` **не импортируются автоматически**. Администратор сам выбирает
нужные CSV на странице «Администрирование»; можно загрузить сразу несколько.
Программа определяет станцию и показатель из названия файла и заголовков,
обрабатывает каждый файл отдельно и показывает результат. Повторный импорт
обновляет значение для того же объекта, показателя, даты и типа ряда. Если
название объекта не найдено в справочнике, оно создаётся автоматически.
Если в CSV есть `lat/lon` (или `широта/долгота`), координаты и регион записываются
автоматически. Иначе программа не придумывает местоположение: объект без
координат не показывается маркером, но его данные доступны для просмотра и
сравнения. Координаты и регион можно добавить в справочнике вручную. В списке
объекты сгруппированы по области/региону; если регион не указан, они собраны в
группу «Область не указана».

База устроена в нормализованном виде: `stations` хранит объекты, координаты и
регионы, `parameters` — показатели и единицы, а `observations` — отдельное значение
для комбинации объекта, показателя, даты и типа ряда. Внешние ключи связывают
наблюдения со справочниками, а составной первичный ключ не допускает случайных
дубликатов. `import_batches`, `import_files` и `import_series` отдельно хранят
историю пакетных загрузок и результат по каждому файлу/ряду.

Для совместимости поддерживаются столбцы `quality_flag` и `quality_note`;
допустимые оценки — `checked`, `suspect`, `unreviewed` и их русские варианты.
Для статистики рассчитываются среднее, медиана, минимум и максимум с датами,
амплитуда, стандартное отклонение и наибольшая скорость роста/снижения между
соседними наблюдениями; отдельно показываются годовые средние, минимумы и
максимумы. Подозрительные точки подсвечиваются на графике и не удаляются
автоматически.

Журнал действий доступен администратору. Резервные копии SQLite создаются
в `data/backups/`; там же остаются пользовательские данные и импортированные
изменения.

## Название и иконка

**HydroGIS** — короткое международное название по назначению: гидрологическая
геоинформационная система. Иконка показывает метку объекта и русло реки.

## Сборка в отдельную папку

Windows:

```bat
build_windows.bat
```

Linux:

```bash
chmod +x build_linux.sh
./build_linux.sh
```

Windows-сборка создаётся в `dist/HydroGIS`. Для переноса копируйте эту папку
целиком, включая `HydroGIS.exe`, `_internal`, `resources`, `static` и
`templates`. Папка `hydro-gis` из Git и виртуальное окружение `.venv` сами по
себе переносимой сборкой не являются.

Сборку для Linux нужно создавать на Linux; Windows и Linux-сборки не взаимозаменяемы.
Linux-сборка включает Python и Python-библиотеки, но использует графические
библиотеки самой ОС (X11/Wayland/GL); собирайте и переносите её на совместимый
Linux-дистрибутив и ту же архитектуру.
