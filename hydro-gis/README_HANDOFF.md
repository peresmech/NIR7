# Передача разработки

## Что проанализировано

Исходная папка `first` содержит:

- 10 реестровых объектов (гидроузлы и гидропосты);
- SQLite-базу с 164873 строками наблюдений;
- таблицы `observations`, `stations`, `rivers`;
- исходные CSV за период примерно с 2010 года;
- прототип PyQt/QWebEngine с Folium-картой;
- параметры расхода и уровней верхнего/нижнего бьефа.

## Формат исходных данных

Для гидроузлов используются CSV с `Dates` и одним параметром:

- `Discharge` — расход воды;
- `Absolute_Levels` — уровень верхнего или нижнего бьефа.

Для гидропостов используется `Absolute_Levels`.

В базе прототипа наблюдение представлено унифицированной записью:

```text
date
value
parameter
station
```

В новой папке сохранён совместимый набор таблиц и добавлены `users`
и `import_log`.

## Архитектурные решения

- настольное приложение запускает локальный Flask-сервер на `127.0.0.1`;
- SQLite остаётся локальной СУБД без сетевого порта;
- карта строится через локально поставляемый Leaflet и тайлы OpenStreetMap;
- графики строятся через Matplotlib;
- гостевой режим не имеет кнопки администрирования;
- администратор может импортировать CSV;
- повторяющиеся записи одной станции/параметра/даты заменяются;
- секретная кука сессии хранится вне репозитория в папке `data/.secret`.
- библиотека Leaflet и картографический интерфейс обслуживаются локально;
  для отображения самих тайлов OpenStreetMap нужно интернет-подключение.

## Ограничения и следующие решения

Перед защитной сдачей нужно согласовать:

1. единый набор параметров для постов и узлов;
2. правила валидации экстремальных и пропущенных значений;
3. необходимость шифрования локальной базы;
4. резервирование исходных CSV и журнала импорта;
5. финальный способ распространения готового `.exe` или standalone-пакета.
