# HydroGIS: описание программы и базы данных

Документ объясняет устройство приложения, путь данных и структуру SQLite. Его
можно использовать как основу для презентации и устного объяснения проекта.

## 1. Назначение

HydroGIS — локальное настольное приложение для хранения, просмотра и первичного
анализа наблюдений гидропостов и гидроузлов. Программа показывает объекты на
карте, строит графики по датам, сравнивает несколько объектов и рассчитывает
сводные показатели. Администратор может загружать CSV и редактировать карточки
объектов; гость может просматривать данные и результаты.

## 2. Из чего состоит приложение

Приложение состоит из нескольких частей:

1. **Окно приложения** создаётся с помощью PyQt и Qt WebEngine. Пользователь
   работает с локальной веб-страницей внутри этого окна.
2. **Интерфейс** написан на HTML, CSS и JavaScript. Он показывает список
   объектов, карту, формы, графики и элементы управления.
3. **Серверная логика** работает на Flask, но слушает только `127.0.0.1`.
   Запросы из интерфейса обрабатываются локально на том же компьютере.
4. **SQLite** хранит справочники и наблюдения в локальном файле
   `data/hydro.db`. При первом запуске рабочая база создаётся из
   `resources/hydro.db`; дальнейшие изменения сохраняются в `data/`.
5. **Pandas** используется для чтения и группировки табличных данных,
   **Matplotlib** — для построения графиков.
6. **Leaflet** отображает карту и маркеры. Подложка OpenStreetMap загружается
   из сети; точки и база остаются локальными.

Схема обработки запроса:

```text
Пользователь → интерфейс HydroGIS → локальный Flask → SQLite
                                      ↓
                              Pandas / Matplotlib
                                      ↓
                         таблица или изображение графика
```

## 3. Основные сценарии работы

### Просмотр и анализ

Пользователь выбирает объект из списка или на карте. Приложение загружает его
наблюдения из SQLite, позволяет задать временной интервал и строит график.
В разделе показателей рассчитываются количество значений, среднее, медиана,
минимум и максимум с датами, амплитуда, стандартное отклонение и скорость
изменения между соседними наблюдениями.

Кнопка **«Сравнить объекты»** открывает всплывающее окно выбора. Два объекта с
данными по расходу предварительно отмечены. В окне можно отметить или снять
галочки у названий, задать показатель, тип ряда и период, затем построить
сравнение по датам или по годам либо скачать CSV. График открывается поверх
карты; кнопка «Закрыть» возвращает к карте. Объекты без значений по выбранному
показателю не дадут линию на графике.

### Импорт CSV

Файлы не загружаются в базу автоматически. Администратор выбирает один или
несколько файлов в разделе администрирования. Программа определяет даты и
показатели по заголовкам, тип ряда — наблюдение или прогноз — по колонке,
а название объекта пытается распознать по имени файла. Администратор может
связать пакет файлов с одной точкой, указав её название, координаты и регион.

Перед сохранением данные преобразуются к общей записи наблюдения. При повторном
импорте совпадение по объекту, показателю, дате и типу ряда обновляет запись,
а не создаёт дубликат. Итог по файлам и рядам записывается в журнал импорта.

### Редактирование точки

В режиме администратора нажмите правой кнопкой на объект в списке слева и
выберите **«Изменить регион и координаты…»**. Откроется карточка объекта:
регион выбирается из общего списка, а координаты можно ввести вручную или
заполнить выбором места кликом по карте. Эти операции меняют справочник
объектов; гостевая учётная запись не может сохранять изменения.

## 4. Структура базы данных

Рабочая база расположена в `data/hydro.db`. Основные таблицы и их назначение:

| Таблица | Что хранит | Ключи и связи |
|---|---|---|
| `stations` | Гидропосты и гидроузлы: идентификатор, название, река, координаты, регион, тип и дополнительные метаданные | `station_id` уникален; поле `downstream_station_id` связывает объект со следующим объектом в логике приложения |
| `parameters` | Справочник показателей и единиц измерения | `code` — первичный ключ |
| `observations` | Одно значение показателя для объекта и даты, с качеством и типом ряда | Составной первичный ключ: `station`, `parameter`, `date`, `series_type`; ссылки на `stations` и `parameters` |
| `users` | Учётные записи и роли `guest`/`admin` | `id` — первичный ключ; `username` уникален; пароль хранится в виде хеша |
| `import_batches` | Один запуск пакетной загрузки и пользователь, который его выполнил | `id` — первичный ключ; `username` связан с `users` |
| `import_files` | Результат обработки каждого файла в пакете | `id` — первичный ключ; ссылки на пакет и, если определён, объект |
| `import_series` | Статистика импорта по показателю и типу ряда для конкретного файла | Составной ключ `file_id`, `parameter`, `series_type`; ссылки на файл и показатель |
| `audit_log` | Действия администратора и системные события | `id` — первичный ключ |
| `import_log` | Совместимость с более ранним форматом журнала импорта | Историческая таблица; текущий отчёт пакетного импорта использует таблицы `import_*` |
| `rivers` | Справочник рек из исходной базы-прототипа | Сохранён для совместимости; основная текущая логика использует название реки в карточке объекта |

Упрощённая схема связей:

```text
stations ─────┐
              ├── observations ─── parameters
              │
              └── import_files ─── import_batches ─── users
                       │
                       └── import_series ─── parameters
```

В `observations` поле `series_type` разделяет `observed` (наблюдения) и
`forecast` (прогноз). `quality_flag` хранит отметку `unreviewed`, `checked` или
`suspect`; пояснение к отметке хранится в `quality_note`.

### Почему наблюдения хранятся отдельно от объектов и показателей

Название объекта и его координаты не повторяются в каждой строке измерения:
они хранятся один раз в `stations`. Название показателя и его единица также
хранятся отдельно в `parameters`. Таблица `observations` содержит только
измерительный факт и ссылки на эти справочники. Это уменьшает повторение данных,
а составной ключ не позволяет случайно записать два значения одного объекта,
показателя, дня и типа ряда.

Схема наблюдений была расширена при инициализации базы, чтобы сохранить
совместимость с исходным прототипом. Поэтому в исходном `resources/hydro.db`
может быть старый набор столбцов; приложение обновляет рабочую копию в
`data/hydro.db`, не меняя исходный файл ресурсов.

## 5. Локальность и безопасность

- Flask привязывается к loopback-адресу `127.0.0.1`; приложение не предназначено
  для публикации в Интернет.
- Пароли пользователей сохраняются как хеш PBKDF2-HMAC-SHA256, а не как
  открытый текст. Секрет сессии хранится в `data/.secret`.
- Доступ к изменению данных проверяется на сервере, а не только скрытием кнопок.
- SQLite-файл **не шифруется автоматически**. Для конфиденциальных данных
  необходимо защищать доступ к учётной записи и диску операционной системы,
  хранить резервные копии в защищённом месте и не передавать папку `data/`
  посторонним.
- При первой установке следует сменить первоначальный пароль администратора.
- Карта требует Интернет для подложки OpenStreetMap; локальные наблюдения,
  справочник объектов и аналитика хранятся на компьютере.

## 6. Краткое объяснение для руководителя

> HydroGIS — настольная геоинформационная система для локальной работы с
> гидрологическими наблюдениями. Интерфейс работает в окне приложения, а
> встроенный сервер обрабатывает запросы на этом же компьютере. Данные хранятся
> в SQLite. Справочник объектов, справочник показателей и таблица наблюдений
> разделены, поэтому координаты и единицы измерения не дублируются в каждой
> записи. Составной ключ наблюдения защищает от дубликатов, а отдельное поле
> типа ряда различает фактические данные и прогноз. Программа импортирует CSV,
> показывает объекты на карте, строит графики, считает статистики и позволяет
> сравнивать несколько станций за период или по годам.

## 7. Что можно развивать дальше

Для развития научной части полезно добавить пространственный поиск объектов,
настраиваемые проверки качества, расширенную статистическую обработку,
шифрование базы на диске, автоматизированные тесты импорта и сравнения, а также
серверный режим с веб-доступом при наличии соответствующего требования.
